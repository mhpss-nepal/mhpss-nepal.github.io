What the model holds, and what it refuses to guess

A method page is only worth reading if it admits what is missing. The second half of this page is a register of things that are not established — and each one is a deliberate blank, not an oversight.

The rule the model exists to enforce

This is a coordination system. It holds service-level information. It does not hold individual-level information.

The coordination function needs to know which organisation provides which service where. It has no case-management mandate, no clinical role, and therefore no lawful purpose for individual records. That single rule disposes of the gender-based violence, unaccompanied-children, suicide and clinical-case scenarios before they arise rather than after.

Fields that do not exist, and are not to be added

Beneficiary name · nickname · identity number · phone number · date of birth · address · diagnosis · assessment score against a person · photograph of a service user · anything from which an individual could be identified.

Mapping to the IASC 4Ws model

The IASC MHPSS 4Ws manual (2012), Table 1, lists 22 items: A to Q, then five marked Optional. The manual does not call any of them core. The fields map onto A to Q. The additions are marked, and every one of them comes from a defect observed in the current reporting workbook rather than from the manual:

AdditionWhy it exists
Bikram Sambat date, stored separately Dates in the current workbook are BS values sitting in Gregorian date cells, so every sort and every period filter is silently corrupted.
Sex and age disaggregation — twelve numeric fields Four age bands — 0–4, 5–17, 18–59, 60 and over — each female, male, and other or not recorded. Partners are already reporting it, as sentences typed into the provider column, because the form has nowhere to put it. It lands in whichever field is nearest.
Funding tag — one or more donors Without it, one organisation reporting under two funding lines looks like two organisations. The manual has no item for the donor; its item C is the organisation an activity is done with, which the form records separately.
Modality — in person, outreach, telephone Helpline contacts were otherwise unrecordable, so remote support sat in a separate tab and was counted nowhere.
Cadre — counsellor, psychologist, psychiatrist Absent from the current form, which is exactly why the three cannot be counted apart today.

The full field-by-field mapping is in hub/docs/DATA_MODEL.md, and the controlled vocabularies are in assets/codes.js — both readable in the repository.

Two rules that do the heavy lifting

Totals are computed, never stored

The CSV export is one flat row per record. The largest defect in the current workbook is subtotal rows sitting in the same column as the data, so a plain sum counts a large share of the reach twice — anyone who opens the file and sums the column gets a materially inflated figure without doing anything wrong.

Record identity is deterministic, so a bad connection cannot inflate a figure

The record id is a hash of organisation, site, date, activity and modality. Submitting the same report twice — a double tap, a page reload, a re-sync after signal returns — produces the same id and therefore one record with a revision history, not two records.

That is record identity, and it is a different question from analytical de-duplication: did two different organisations report the same site on the same day, and if so did they reach the same people? The coordination view flags those. It does not resolve them, because it cannot — only the two organisations know. The flag distinguishes three readings: different activities (likely different people), one organisation reporting under two funding tags (attribution, not duplication), and the same activity by two organisations (needs a conversation).

Register of what is not established

“Not established” is an acceptable answer. A wrong figure is not.

Partly open   IASC 4Ws activity codes

The code list of the 2012 manual (Table 2: 11 codes, 45 subcodes) is in hand. Where an activity matches a subcode directly, the subcode sits on the activity in the code list and a report carries it without anyone typing it — eight activities. Where the subcode depends on the cadre of whoever delivered the service or on what it covered — specialised care, medication, referral, IEC material, assessment — the rule is recorded and no subcode is written. A guessed code would look right and be wrong, which is worse than empty, because a wrong code propagates into every aggregate downstream and nobody can see it.

Two questions stay open: whether a helpline contact and a coordination meeting belong in a 4Ws activity list at all, and whether the 2012 codes remain the basis — an updated set in a May 2024 draft toolkit has not been obtained.

Not obtained   Bikram Sambat conversion table

No calendar conversion is performed anywhere in this system. Nepali month lengths vary from year to year and cannot be computed from a formula — conversion needs a lookup table of days per month per BS year. A verified table for 2082–2085 from a Government of Nepal source is required first. Both calendars are stored separately in the meantime and everything sorts on the Gregorian field.

Not agreed   The site list

Derived from the holding-centre roster of the daily reporting workbook, the list of centres from the District Administration Office, Nuwakot, of 29 Bhadra 2083, and sites appearing in submitted reports. EDCD and the MHPSS Technical Working Group have not signed it off. Sites that appear in reports but were never on the roster are flagged separately and never counted as coverage gaps — a site nobody ever listed as a service point cannot be counted as one that was missed.

Not agreed   The activity list

Consolidated from what partners have actually submitted, not from an agreed taxonomy.

Unresolved   Contacts versus people reached

The reporting sheet counts service contacts; the national 5W counts people reached. Until NDRRMA and EDCD rule on this in writing, no figure from the sheet is submitted. See Layer 3.

Not run   Accessibility audit

Colour contrast has been checked numerically across every surface in both light and dark modes, and the chart palette was validated for colour-vision separation. That is not a full accessibility audit, and none has been run.

Partial   Nepali translation

Pages carry a language switch, but most text is not yet in Nepali. A page that is not available in Nepali says so. On a page that is, any string still awaiting its Nepali version shows in English, a machine draft is announced as translated automatically, and the English version is stated to be the authoritative one. Clinical wording and consent text stay in English whatever the dictionary holds: a machine-rendered PHQ-9 is not the PHQ-9.

Location granularity

Site-level, coded, and no finer. No GPS coordinates, no ward-level detail below the site. The 4Ws manual leaves granularity open — town names, neighbourhood names or GPS — and in a displacement setting the coarsest level that still supports referral is the right level.
